# PipeFree 集成测试

本目录包含了完整的集成测试套件，用于验证 PipeFree 客户端与服务端的交互能力和系统健壮性。

## 测试文件说明

### 1. `integration_test.go` - 核心集成测试
测试服务端与客户端的基本交互能力：

- **TestServerClientInteraction**: 主要集成测试
  - 服务端创建流水线并写入 etcd
  - 客户端启动后监听已存在的对象
  - 验证状态变化的实时同步
  - 测试删除事件的处理

- **TestClientResilience**: 客户端容错能力测试
  - 快速批量创建对象
  - 验证事件处理的完整性

- **TestConcurrentClients**: 多客户端并发测试
  - 多个客户端同时监听同一资源
  - 验证事件广播的正确性

### 2. `performance_test.go` - 性能压力测试
测试系统在高负载下的表现：

- **TestHighConcurrencyEvents**: 高并发事件处理
  - 100个对象的并发创建/更新/删除
  - 验证事件处理的完整性和性能

- **TestCacheConsistency**: 缓存一致性测试
  - 多客户端缓存数据一致性验证
  - 更新同步的正确性检查

- **TestNetworkPartition**: 网络分区恢复测试
  - 模拟网络分区期间的快速更新
  - 验证恢复后的数据一致性

- **BenchmarkInformerThroughput**: Informer 吞吐量基准测试
- **BenchmarkCacheQuery**: 缓存查询性能基准测试

### 3. `edge_cases_test.go` - 边界条件测试
测试各种异常和极端情况：

- **TestEdgeCases**: 边界条件测试
  - 空字符串字段处理
  - 极长字符串处理
  - 特殊字符和 Unicode 支持
  - 极端时间戳处理

- **TestInvalidData**: 无效数据处理
  - 无效 JSON 数据的容错处理
  - 缺少字段的数据处理
  - 类型不匹配数据的处理

- **TestResourceVersionHandling**: 资源版本处理
  - 版本递增更新的正确性
  - 乱序更新的处理机制

- **TestLargeObjectHandling**: 大对象处理
  - 大型配置对象的存储和检索
  - 大对象更新的性能测试

## 运行测试

### 前置条件
1. 确保 etcd 服务正在运行
2. 确保数据库连接正常
3. 配置文件 `config.yaml` 存在且正确

### 运行所有测试
```bash
# 运行所有集成测试
go test ./test/... -v

# 运行特定测试
go test ./test/ -run TestServerClientInteraction -v

# 运行性能测试
go test ./test/ -run TestHighConcurrencyEvents -v

# 运行基准测试
go test ./test/ -bench=. -v
```

### 测试参数调整
可以通过修改测试常量来调整测试规模：

```go
// 在 performance_test.go 中
const (
    numObjects    = 100  // 调整对象数量
    numOperations = 300  // 调整操作数量
)
```

## 测试场景详解

### 核心场景：服务端先启动，客户端后启动
这是最重要的测试场景，模拟真实环境中的情况：

1. **服务端创建流水线**
   - 在数据库中创建 NodeExec 记录
   - 将数据写入 etcd
   - 模拟流水线开始执行

2. **客户端启动监听**
   - 客户端在流水线运行过程中启动
   - 通过 List/Watch 机制获取当前状态
   - 验证能否正确同步已存在的对象

3. **状态变化同步**
   - 服务端更新流水线状态（Pending → Running → Succeeded）
   - 客户端实时接收更新事件
   - 验证事件顺序和数据一致性

4. **资源清理**
   - 服务端删除流水线
   - 客户端接收删除事件
   - 验证缓存清理的正确性

### 容错能力测试
- **网络分区恢复**: 模拟网络中断后的数据同步
- **无效数据处理**: 测试系统对损坏数据的容错能力
- **高并发处理**: 验证系统在高负载下的稳定性
- **资源版本冲突**: 测试乱序更新的处理机制

## 预期结果

### 成功指标
- ✅ 所有事件都被正确接收和处理
- ✅ 缓存数据与 etcd 数据保持一致
- ✅ 系统在异常情况下保持稳定
- ✅ 性能指标满足预期要求

### 性能基准
- **事件处理延迟**: < 100ms
- **缓存查询延迟**: < 1ms
- **并发处理能力**: > 1000 events/sec
- **内存使用**: 合理范围内

## 故障排查

### 常见问题
1. **etcd 连接失败**
   - 检查 etcd 服务状态
   - 验证连接配置

2. **数据库连接问题**
   - 检查数据库服务
   - 验证连接字符串

3. **事件丢失**
   - 检查网络连接稳定性
   - 验证 Watch 机制是否正常

4. **缓存不一致**
   - 检查 Informer 同步状态
   - 验证资源版本处理

### 调试技巧
- 使用 `-v` 参数查看详细日志
- 检查 etcd 中的实际数据
- 监控系统资源使用情况
- 分析事件时序和顺序
